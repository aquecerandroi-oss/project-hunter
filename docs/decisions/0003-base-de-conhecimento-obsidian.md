# 0003 — `obsidian/` como base de conhecimento viva do projeto (separada do `vault/` pessoal)

- **Status:** aceito
- **Data:** 2026-09-05
- **Contexto:** em 2026-09-05 o dono pediu que toda a evolução do sistema fique documentada em Markdown compatível com Obsidian, numa estrutura fixa (`00-HOME.md`, `01-ARCHITECTURE/`, `02-MARKET/`, `03-TRADING/`, `04-AGENTS/`, `05-EXPERIMENTS/`, `06-DECISIONS/`, `07-BUGS/`, `08-CHANGELOG/`, `09-OPERATIONS/`, `10-PERFORMANCE/`), com links internos `[[...]]`, experimentos numerados (`EXP-0001-...`) e versões de estratégia nunca sobrescritas. O repositório já tinha um `vault/` (memória pessoal do agente Sexta-feira, servido pelo `obsidian-mcp` via `.mcp.json` e protegido por hook que só permite escrita via MCP) e a pasta `docs/` (arquitetura, ADRs, planos, relatórios de milestone).
- **Decisão:** criar `obsidian/` na raiz como a base de conhecimento **do projeto**: Markdown puro, versionado no git, escrito e atualizado pelos agentes com as ferramentas normais de arquivo sempre que uma implementação, bug, decisão ou mudança de estratégia for significativa. `vault/` continua sendo o caderno **pessoal** do Sexta-feira (notas diárias, coisas que o dono pede para lembrar), acessível só por MCP. `docs/` continua sendo a documentação normativa (specs, ADRs, planos, relatórios §77); as páginas de `obsidian/` resumem e linkam para `docs/` em vez de duplicar, e `06-DECISIONS/Architecture Decisions.md` é o índice legível dos ADRs. Quando o dono abrir a pasta `obsidian/` no Obsidian, `00-HOME.md` é a porta de entrada.
- **Alternativas consideradas:** (a) usar o `vault/` existente para tudo — rejeitado porque mistura memória pessoal com documentação de produto e porque o hook impede os implementadores de atualizar docs junto com o código; (b) só `docs/` — rejeitado porque o dono quer navegar como knowledge base com links `[[...]]`, experimentos e performance por agente, o que não cabe no formato normativo de `docs/`.
- **Consequências:** `obsidian/` entra na "definition of done" de cada milestone (seção OBSIDIAN UPDATED do relatório); `08-CHANGELOG/Changelog.md` recebe uma entrada por commit lógico; cada experimento significativo ganha `05-EXPERIMENTS/EXP-NNNN-<slug>.md`; cada versão de estratégia (`volume_anomaly_v1`, `_v2`, ...) tem sua página com o que mudou, por quê e resultados antes/depois; `07-BUGS/` registra bugs relevantes abertos e resolvidos. O hook `vault-mcp-only.mjs` **não** cobre `obsidian/`.
- **Referências:** diretiva "PROJECT HUNTER — IMPLEMENTAÇÃO FUNCIONAL" (2026-09-05, PARTE 12), `vault/README.md`, `.claude/agents/sexta-feira.md`, `docs/WORKFLOW.md`.
