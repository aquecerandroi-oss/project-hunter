# 0001 — Adotar o fluxo do vibe-coding-toolkit para o desenvolvimento

- **Status:** aceito
- **Data:** 2026-09-04
- **Contexto:** o PROJECT HUNTER será construído em milestones por um agente (Claude Code) orquestrando subagentes. Sem um fluxo explícito, o risco é o clássico: agente que codifica a primeira interpretação, constrói além do pedido, dois agentes sobrescrevendo o mesmo arquivo, lições caras reaprendidas a cada sessão, lint que ninguém zera. O usuário pediu que o repositório [soumatheusgomes/vibe-coding-toolkit](https://github.com/soumatheusgomes/vibe-coding-toolkit) fosse usado como base do método.
- **Decisão:** adotar as sete peças do toolkit adaptadas ao Hunter: (1) sessão principal orquestra e commita, especialistas implementam (`CLAUDE.md` + `.claude/agents/`); (2) brainstorm → plano → ondas → revisão → commit, com classificação spike/bounded/architectural; (3) execução em ondas paralelas com `Files:`/`Depends-on:` e commit serializado (`.claude/rules/parallel-subagent-driven-development.md`); (4) quality gates com regras copiadas byte a byte (`packages/config/eslint`), teto de 350 linhas nos dois lados (TS e Python), regra nova nasce em `warn`; (5) memória em duas camadas (`.claude/memory/` + `docs/decisions/`); (6) hooks fail-open com `parseHookEvent` (`.claude/hooks/`); (7) escolha explícita de tier de modelo por despacho.
- **Alternativas consideradas:** GitHub Spec Kit e BMAD (metodologias mais pesadas, com personas de PM e cerimônia formal; o toolkit já cobre o que o Hunter precisa e é o pedido explícito do usuário); `aia-harness:init` (gera a estrutura automaticamente, mas exige plugin instalado na sessão do usuário e produziria um roster genérico em vez do roster específico do domínio quant).
- **Consequências:** toda tarefa de milestone precisa de brief com arquivos e dependências antes de ser despachada; implementadores nunca commitam; revisões são painéis independentes; `risk-engine-guardian` e `security-reviewer` são revisores obrigatórios nos caminhos que movem dinheiro ou tocam auth. Custo: mais tokens por milestone (3–10× segundo a Anthropic para multiagente), compensado por paralelismo e menos retrabalho. Plugins Superpowers, Ponytail e Caveman são recomendados mas instalados pelo usuário na própria sessão (`docs/WORKFLOW.md` §1). Revisitar após o M2: medir se a divisão em ondas está rendendo paralelismo real ou só cerimônia.
- **Referências:** `docs/WORKFLOW.md`, `CLAUDE.md`, `docs/plans/M0.md`, README do toolkit (MIT).
