**Owner:** frontend-specialist (web) with the small API change (backend-specialist skills; one agent). **Reviewer afterwards:** code-reviewer. **Do not commit.** **Operational rule: never a background shell; every command in the foreground with a timeout <= 5 min; do not touch `.env*`.** Base: `main` at `b6f5c2c`. ## Symptom (Everton, VPS, 2026-09-08 ~03:50Z)
`/ever/markets` shows **every** row as `atrasado 1min` while the VPS is fresh: all four shard heartbeats and the BTC/ETH/SOL ticker timestamps are within 1 s of the server clock, the WebSocket is accepted, prices move. `QualityBadge` (`apps/web/components/markets/quality-badge.tsx`) re-derives the age of the required components (`ticker`, `book`, `mark`) with `useAgeTicker` = the **viewer's** `Date.now()` (`apps/web/hooks/useAgeTicker.ts`). A viewer clock ~60 s ahead turns every fresh row into "atrasado 1min"; a clock behind hides real staleness. The API already computes `quality` with its own clock and ships `stale_after_ms`; the client must age against the same clock.

## Deliver
1. **API**: every response that carries `stale_after_ms` (`MarketListPage`, `MarketDetailOut`, and the system/workers payload if it ages heartbeats) also carries `server_now` (ISO 8601 UTC, the instant the response was built). Add to the schemas (`apps/api/hunter_api/schemas/markets.py`, wherever `stale_after_ms` lives) and services; unit tests assert it is present and monotonic with the row timestamps. Regenerate `apps/web/lib/api/types.ts` the way the repo does (`pnpm --filter web generate:api` or the documented command; `openapi.json` is gitignored — do not commit it).
2. **Web**: `useAgeTicker` gains a server offset: `useServerClock(serverNowIso, receivedAtMs)` computes `offset = serverNow − receivedAt` once per response and every tick returns `Date.now() + offset`. `QualityBadge`, `MarketRow`, the market detail view, the summary chips and the System page workers card age against that clock. When a realtime tick arrives through the WebSocket with its own `ts`, ages keep using the server clock (never the viewer's). If `server_now` is missing (old API), fall back to the viewer clock **and** render a tiny muted hint "relógio local" so the fallback is visible, not silent.
3. **Honesty**: a row whose components are genuinely older than `stale_after_ms` on the server clock still reads `atrasado`; a viewer clock skew of ±5 min must not change any badge. Tests (Vitest, `apps/web/tests/`): skewed viewer clock ahead and behind → badges unchanged; missing `server_now` → fallback + hint; realtime tick refreshes the age.
4. **Check the screen with real data** before reporting (rule: front always polished): run the web against the VPS API only if a documented way exists (`docs/DEPLOYMENT.md`), otherwise against the local stack; paste what the badge shows. The self-signed VPS certificate blocks the in-app browser; say so if you cannot reach it.
