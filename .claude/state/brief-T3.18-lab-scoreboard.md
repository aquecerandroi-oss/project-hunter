## Deliver
1. **API `GET /orgs/{org}/lab/scoreboard?as_of=`**: one row per `strategy_version` that has ever emitted (active, deprecated and draft-with-signals alike), computed in SQL with the plantão's definitions: `version` (key, version, purpose, status, activated_at, code_ref), `emitted`, `evaluable` (outcomes with `r_multiple` not null), `pending`, `no_entry`, `censored`, `distinct_days`, `distinct_markets`, `hit_rate` = alvo entre toques resolvidos (numerator, denominator both returned), `net_profit_rate` = lucro líquido entre avaliáveis (num/den), `expectancy_r` (mean net R), `profit_factor` (null + reason when a side is empty), `sum_r`, `worst_streak` (consecutive losses), `max_drawdown_r` on the cumulative-R curve, `maturity` = `{evaluable, days, threshold: {outcomes: 100, days: 30}, mature: bool}`, and **`verdict`**: `inconclusivo` when not mature; when mature: `validada` if `expectancy_r > 0` and `profit_factor > 1`, else `reprovada`. Money fields are **not** computed by the API (the web applies the ruler). `as_of` freezes the population (`emitted_at <= as_of`), default now. Tenant-scoped like the other Lab routes. Unit + integration tests with a seeded population that exercises every null reason.
2. **API `GET /orgs/{org}/lab/curve?version_id=&as_of=`**: the cumulative net R series per resolved outcome, ordered by exit time (`[{ts, r, cum_r}]`), capped at 2 000 points with `truncated` flag; one call per version. Tests.
3. **Web — Placar** (new tab or the top of `/lab`): one card per version, ordered active first then by `sum_r`: name + purpose chip (`pesquisa`/`paper`), status, since; the verdict as the dominant element (chip: `inconclusiva` muted, `validada` positive, `reprovada` negative) **with the maturity bar** ("37 de 100 resultados · 2 de 30 dias"); then the numbers in money through the T3.17 ruler (resultado acumulado USDT/BRL, média por operação) **and** in the research units behind the existing "Detalhes de pesquisa" toggle (hit rate with denominator, expectancy R, PF or its reason, worst streak, max DD in R). Empty card states say why (no signals yet / all pending).
4. **Web — Curva**: one chart, one line per version (cumulative simulated result in USDT through the ruler; toggle to R), same colours as the cards, legend with the verdict chip, hover shows date and value; honest empty state. Use the charting approach already in the repo (the equity curve of `/portfolio`) — do not add a new charting library.
5. **Copy** in plain Portuguese: "validada"/"reprovada"/"inconclusiva" always next to the rule that produced it ("régua: 100 resultados e 30 dias; validada = expectancy > 0 e PF > 1"). Never "lucro garantido"; always "simulado".
6. **Tests**: API (unit for the verdict function with every branch; integration for the SQL), web (cards, verdict, maturity bar, toggle, curve empty/filled). `pnpm --filter web lint|typecheck|test`, `uv run pytest apps/api/tests/unit -q -p no:randomly`, the new integration file, `ruff`, `pyright`, `check_file_size.py`.
