## Finding (security-reviewer, T3.15d)
`DATABASE_URL` and `DATABASE_URL_MIGRATIONS` are the same credential (`hunter`: `rolsuper=true`, `rolbypassrls=true`); `hunter_app`/`hunter_worker` are `NOLOGIN` roles granted to that login (`infra/migrations/ddl/security.py:12`). `SET LOCAL ROLE hunter_app` in `session.py` is a voluntary reduction, reversible with `RESET ROLE`. An RCE in any runtime service can therefore `ALTER TABLE … DISABLE ROW LEVEL SECURITY` or activate a `paper` version. Removing `DATABASE_URL_MIGRATIONS` from the runtime (T3.15d) does not change this.

1. **Design** (write it before the migration; Everton must see it — the change of credentials is his to schedule): a login role `hunter_runtime` (`NOSUPERUSER NOBYPASSRLS NOCREATEROLE NOCREATEDB`, `LOGIN`) that is a member of `hunter_app` and `hunter_worker` **only**; `SET ROLE` remains possible only into those two; the owner login `hunter` stays for `migrate`/`ops`. List every statement the runtime executes that needs owner today (grep: `CREATE`, `ALTER`, `TRUNCATE`, partition creation, `LISTEN/NOTIFY` on owned objects, `pg_advisory_lock` — fine) and what breaks; the partitions job already moved to `ops` (T3.15e).
2. Migration `0015_runtime_login_role`: creates the role idempotently **without a password** (the password is set out-of-band by the operator: `ALTER ROLE hunter_runtime PASSWORD …` — never in the repo), grants membership, `GRANT CONNECT`, default privileges as `hunter_app`/`hunter_worker` already receive; downgrade drops the role only if it owns nothing. Tests on testcontainers: with `DATABASE_URL` pointing at `hunter_runtime`, the API/worker test suites' RLS tests still pass (`test_isolation.py`, `test_shadow_decisions.py` one file each), and `ALTER TABLE portfolios DISABLE ROW LEVEL SECURITY` / `UPDATE strategy_versions SET purpose='paper'` are refused.
